# Как устроен конфиг

Коротко: конфиг - это список твоих проектов и личные настройки. Всё, что можно узнать из самого
проекта, tim узнаёт каждый раз заново и в конфиг не пишет. Поэтому он почти не устаревает.

Файл лежит в `~/.config/tim/config.toml`, другой путь можно задать через `TIM_CONFIG`.
Пример со всеми разделами: [config.example.toml](../config.example.toml).

## Что tim понимает сам

Это не хранится в конфиге, а определяется по файлам проекта при каждом запуске:

| Что | Откуда |
|---|---|
| стек | `artisan` - Laravel, `go.mod` - Go, `package.json` - Node, `pyproject.toml` - Python и т.д. |
| команда запуска | `composer dev`, `artisan serve`, скрипт `dev` в `package.json`, `make dev`, `go run`, compose-файл |
| пакетный менеджер | по lock-файлу: pnpm, yarn, bun или npm |
| версия PHP | `require.php` в `composer.json` |
| Python | uv по `uv.lock`, иначе venv в папке проекта |

Пример того, как это выглядит: `tim serve blog --dry-run` покажет команду, ничего не запуская.

## Что лежит в конфиге

После `tim config init` и `tim sync` он выглядит примерно так:

```toml
dev = "/Users/me/Dev"   # корень проектов
wrapper = "app"         # клоны лежат в подпапке app

[[project]]
  name = "shop"
  path = "shop/app"
  port = 8010
  db = "pgsql:shop"
```

## Когда в конфиг заглядывают

Только когда ответа нет в самом проекте. Обычно хватает команды, файл открывать не нужно.

**Где проект живёт на сервере.** Поля `ssh` (алиас из `~/.ssh/config`) и `deploy` (путь на сервере).
Их знаешь только ты, хотя `tim sync --ssh` подбирает алиас по адресу сайта.

**Боевой домен.** Поле `url`. Из локального `.env` его не узнать, там обычно localhost.
`tim sync --remote` спрашивает nginx на серверах из поля `ssh` и сам сопоставляет домены с проектами.

**Свой способ запуска.** Если догадка не подошла:

```toml
[[project]]
  name = "legacy"
  path = "legacy"
  serve = "php -S 0.0.0.0:9000 -t www"
```

**Порт.** Тоже руками не нужен. Проекту без порта tim при первом `tim serve` подбирает свой,
которого нет ни у кого в реестре, и записывает: "закрепил за blog порт 8002". `tim sync` раздаёт
порты сразу всем проектам, которые можно запустить. Если в `APP_URL` есть порт, берётся он.
Поменять - поле `port`.

## Личное

```toml
[shell]
  motd = true            # сводка при открытии терминала
  cd_info = true         # проект и ветка при входе в папку

[shell.aliases]
  gs = "git status -sb"

[groups]
  shop = ["shop", "shop-admin"]   # tim serve @shop поднимет оба

[[task]]                 # tim each deps - во всех проектах с composer.json
  name = "deps"
  marker = "composer.json"
  run = "composer outdated --direct"
```

## Цели обхода VPN

```toml
[[host]]
  addr = "203.0.113.5"   # адрес, подсеть, домен или as:N
  label = "prod"
```

Их заводит `tim direct`, убирает `tim direct rm`. Страж маршрутов берёт цели отсюда и перечитывает
файл каждые 10 секунд, перезапускать его не надо. Адрес и подсеть идут как есть, домен - его адреса
из DNS, `as:N` - сети компании из RIPE, список обновляется раз в сутки. Подробнее: [VPN и маршруты](03-vpn.md).

## Важно

- tim переписывает конфиг через TOML-кодировщик, комментарии при этом теряются. Прежняя версия
  файла остаётся рядом в `config.toml.bak`.
- `sudo tim ...` работает с твоим конфигом, а не с пустым конфигом root, и после записи
  возвращает файл тебе.
