# Состояние сервера

```sh
tim server prod                 # алиас из ~/.ssh/config
tim server shop                 # проект с полем ssh
tim server root@203.0.113.10    # или адрес напрямую
```

Один заход по ssh. tim отправляет скрипт через стандартный ввод, ничего не ставит
и ничего не меняет. На сервере нужен только обычный Linux - проверки рассчитаны на Debian и Ubuntu,
на других системах часть пропустится, а не упадёт.

## Что смотрится

- место на дисках и inode (бывает, что место есть, а файл не создать);
- память, swap и нагрузка на ядро;
- упавшие службы systemd;
- нужна ли перезагрузка после обновления ядра или libc;
- ждущие обновления безопасности;
- какие порты слушают на всех адресах, то есть видны из интернета;
- настройки входа по ssh и защита от перебора: fail2ban или CrowdSec;
- проверка конфига nginx и сроки сертификатов Let's Encrypt на диске.

## Про sudo

Часть проверок требует root: настройки sshd, `nginx -t`, сертификаты. tim пробует их через
`sudo -n` - без пароля sudo не спрашивает, а отказывает, и такие проверки помечаются
"не проверено". Под root или с `NOPASSWD` проверится всё.

## Частые находки и что с ними делать

**PermitRootLogin yes и PasswordAuthentication yes.** Под root можно подбирать пароль.
Если на сервер ходят по ключу, в `/etc/ssh/sshd_config`:

```
PermitRootLogin prohibit-password
PasswordAuthentication no
```

Затем `sshd -t` (проверка) и `systemctl reload ssh`. Перед выходом открой новую сессию
и убедись, что вход по ключу работает.

**База слушает на всех адресах.** MySQL, PostgreSQL или Redis на `0.0.0.0` доступны из интернета.
Поставь `bind-address = 127.0.0.1` (MySQL) или `listen_addresses = 'localhost'` (PostgreSQL),
а снаружи ходи через туннель: `tim tunnel db shop`.

**Нужна перезагрузка.** Ядро или libc обновились, но работают старые - со старыми дырами.
Перезагрузи сервер в спокойное время.

**Необычные открытые порты.** tim не знает, что это. Посмотри на сервере `ss -tlnp` - там видно,
какой процесс слушает порт.

**Нет защиты от перебора.** Боты подбирают пароли к ssh круглые сутки. `apt install fail2ban` -
и он сразу банит их по журналу ssh. CrowdSec делает то же и ещё делится чёрными списками с другими
серверами. ufw от перебора не спасает: он закрывает порты, а 22 остаётся открытым. Если вход только
по ключу, перебор не опасен - tim пишет это серым, а fail2ban просто уберёт шум из журнала.

**Упавшие fwupd и networking на VPS.** fwupd обновляет прошивки, которых у виртуальной машины нет,
а старый ifupdown падает, когда сетью управляет netplan. tim показывает их одной серой строкой.
Убрать из списка: `systemctl reset-failed`.

## Кто ломится

```sh
tim server prod --attacks             # журналы за сутки
tim server prod --attacks --since 3d
```

tim читает журналы, которые уже есть на сервере, и ничего не ставит. Удачные входы по ssh: вход
с адреса, который перед этим перебирал пароли, - красная строка, вход по паролю - жёлтая. Перебор:
сколько попыток, с каких адресов и какие имена подбирали. Пробы сайта: кто искал `.env`, `.git`,
`wp-login.php` и панели баз, и что из этого получило 200. Ещё файрвол ufw, баны fail2ban и CrowdSec
и владельцы сетей, откуда больше всего стучались. Свои проверки `tim audit` в счёт не идут.

Журналы ssh и ядра читают только root и группы `adm` и `systemd-journal`. Под пользователем сайта
tim честно напишет "не прочитан"; дать доступ: `sudo usermod -aG adm,systemd-journal <пользователь>`.
Журналы сайта панели хостинга держат в папке пользователя - их tim находит сам.

На клавише `a` на экране сервера - то же самое.

## Кто ходит на сайты

```sh
tim server prod --traffic             # журналы запросов за час
tim server prod --traffic --since 1d
```

Журналы nginx или apache: запросов всего и в минуту, график по минутам, доли ответов, адреса
с владельцами сетей (бот от человека отличается сразу), пути, 5xx с путями, 404. Если журнал
пишет время ответа последним полем - p50, p95 и самые медленные пути. Сверху находки: 5xx больше
процента, адрес-обжора, медленные ответы, тихий сайт. Журнал бэкенда за фронтендом панели
пропускается - там те же запросы. Читается хвост в 30 тысяч строк; если хвост короче окна, рядом
написано, с какого времени.

## Все серверы

```sh
tim servers            # серверы проектов из реестра
tim servers --all      # весь ~/.ssh/config
tim servers prod demo
```

Таблица: состояние, uptime, нагрузка, память, диск, проекты. Хост с несколькими алиасами идёт
одной строкой; алиас с root в приоритете, у него отчёт полный. По 6 серверов за раз, 15 секунд
на каждый. На экране: enter - сервер, `a` - кто ломится, `s` - ssh.

## Когда кончится диск

```sh
tim servers --record    # замер в журнал сейчас
tim servers --install   # и раз в 6 часов
```

Нужны шесть замеров за сутки и больше - при шаге в 6 часов это сутки-двое. Потом `tim server prod` пишет, сколько уходит в сутки и когда
место кончится. Меньше двух месяцев - жёлтая находка, меньше двух недель - красная. Замер
по расписанию ходит по ssh сам: ключ должен работать без вопросов. `--uninstall` убирает.

## В обходе проектов

`tim check --servers` добавляет колонку "сервер": худшая находка сервера, под строкой подробность.
На хост заходит один раз, сколько бы проектов на нём ни жило. `tim check --install --servers` -
то же каждый день.

## Отчёт в файл

```sh
tim server prod --json > prod.json
tim server prod --traffic --json
tim servers --json
```
