# Первый запуск

Пять минут от установки до `tim go`. Конфиг руками писать не придётся.

## Поставить

```sh
go install github.com/TimurTurdyev/tim@latest
```

Или из клона репозитория: `make install`. Там же ставятся man-страницы, `man tim` заработает сразу.

## Подключить к shell

```sh
tim init
```

Команда сама найдёт `~/.zshrc` или `~/.bashrc`, допишет туда одну строку и скажет, что делать дальше.
Открой новое окно терминала.

Зачем это нужно. Процесс не может поменять папку или `PATH` у оболочки, которая его запустила.
Поэтому `tim go` и `tim php use` работают через маленькую функцию в shell. Она же подключает
дополнение по Tab и подсказку при входе в папку проекта.

## Найти свои проекты

```sh
tim config init
```

tim ищет git-клоны в первой существующей из папок `~/Dev`, `~/Projects`, `~/code`, `~/src` и
предлагает отметить, какие взять в реестр. Если клоны у тебя лежат во вложенной папке
(`shop/app`, `blog/app`), tim это заметит и будет звать проекты по внешней папке: `shop`, `blog`.

Другая папка или без вопросов:

```sh
tim config init --root ~/work --all -y
```

## Дать tim подсмотреть порты и базы

```sh
tim sync
```

Из `.env` каждого проекта берутся порт (`APP_URL`) и база (`DB_CONNECTION`, `DB_DATABASE`).
Заполняются только пустые поля, своё tim не перезаписывает.

## Попробовать

```sh
tim go             # выбор проекта с поиском, Enter - и ты в папке
tim serve shop     # dev-сервер по стеку проекта
tim status         # что происходит с машиной
tim                # главный экран
```

## Если что-то не так

`tim doctor` проверяет конфиг, реестр, подключение к shell, `PATH` и менеджеры версий и говорит,
что именно поправить. Справка по любой команде: `tim <команда> --help`, там же есть примеры.
