# Быстро посмотреть сайт клиента

Пришёл клиент: "посмотрите, всё ли у нас в порядке". Вот что можно выяснить за пару минут,
не заходя на сервер.

## Общая картина

```sh
tim site example.com
```

Где сайт живёт (адреса, страна, провайдер), когда кончается домен и сертификат, что отвечает
сервер, куда ведут редиректы и на чём сделан сайт.

```sh
tim domain example.com --map
```

Всё про домен разом: регистрация, NS, почта, поддомены из логов сертификатов, на каких адресах
что работает. `--map` рисует карту в HTML и открывает её - удобно показать клиенту.
CNAME в никуда и имена под захват у чужого сервиса - красным.

## Дыры, которые видно снаружи

```sh
tim audit example.com
tim audit shop            # проект с адресом сайта в реестре
```

tim смотрит сайт так, как его видит бот: открыты ли `.env`, `.git`, дампы базы, журналы Laravel,
phpinfo и Telescope, включена ли отладка, есть ли HSTS, CSP и защита от фрейма, правильные ли флаги
у кук, переходит ли http на https, какие версии TLS принимает сервер, отдаёт ли он промежуточный
сертификат, не устарели ли версии nginx, PHP и WordPress, отвечают ли наружу порты баз. Дальше то,
что видит посетитель и поисковик: robots и sitemap, мягкая 404, www и без www, title, description,
lang, h1 и favicon, смешанное содержимое, битые ссылки с главной, сжатие, HTTP/2, кэш статики, первый
байт, записи CAA и DNSSEC, не живут ли все NS в одной сети. У каждой находки - почему это плохо и что
сделать. Открытый файл засчитывается только по содержимому: заглушки отдают главную на любой адрес.
Ещё поддомены: CNAME на чужой сервис, где имя никто не занял, - такое имя могут захватить.

```sh
tim audit example.com --html     # отчёт для клиента одной страницей, audit-example.com-<дата>.html
tim audit example.com --md       # то же в Markdown, вставить в письмо или задачу
```

Проверяй свои сайты и те, что попросили проверить. Если у проекта нет адреса сайта, его найдёт
`tim sync --remote` в конфигах nginx на серверах.

## Почта

```sh
tim mail example.com
```

MX, SPF, DKIM и DMARC: что настроено, что не так, и готовые DNS-записи для недостающего.
Это самая частая проблема небольших сайтов: письма с формы уходят в спам или от имени домена
можно отправить что угодно.

## Сертификат и DNS

```sh
tim cert example.com    # кто выдал, на какие имена, когда истекает, цепочка
tim dns example.com     # записи, CAA - кому можно выпускать сертификаты, DNSSEC
```

## Скорость ответа

```sh
tim http https://example.com
```

Один запрос по фазам: DNS, соединение, TLS, первый байт, загрузка. Сразу видно, где тормозит:
долгий первый байт - это сервер или приложение, долгий TLS - далеко или плохо настроено.

## Как сайт выглядит в мессенджерах

```sh
tim og https://example.com
```

Заголовок, описание и картинка, которые покажут Telegram и соцсети, и чего не хватает для
большого превью. Частая находка - вместо картинки превью стоит маленький логотип или её нет совсем.

## Фронтенд не может достучаться до API

```sh
tim cors https://api.example.com/orders --origin https://example.com --method POST --header Authorization
```

Делает то же, что браузер, и говорит, какой заголовок мешает. Самое частое: звёздочка
в `Access-Control-Allow-Headers` не покрывает `Authorization`, а с куками звёздочка не работает вовсе.

## Сайт падает во время работ

```sh
tim watch https://example.com
```

Уведомление, когда сайт упал и когда поднялся. Удобно держать открытым во время деплоя или переезда.

## Все свои сайты разом

Если домены записаны в реестре (поле `url`, заполняет `tim sync --remote`):

```sh
tim check              # git, сайт, сертификат, почта, срок домена - одной таблицей
tim cert               # сроки всех сертификатов
tim mail --all         # почта всех доменов
```
