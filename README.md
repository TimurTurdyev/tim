# tim

Помощник в терминале для разработчика: сеть мимо VPN, серверы, сайты, машина.
Один бинарник на Go плюс маленькая функция для shell.

Вырос из набора zsh-функций, которые копились годами: подключиться к серверу, когда
включён VPN, поднять туннель к базе, посмотреть, кто занял порт, проверить сертификат.
В какой-то момент их стало тридцать, они перестали помещаться в голове и начали тормозить
открытие терминала. Так появился `tim`: то же самое, но одной командой, с подсказками
и без задержки на старте.

```sh
tim ssh prod                # подключиться мимо VPN, если он мешает
tim direct example.org      # пустить сайт мимо VPN целиком
tim ports                   # что запущено и кем, забытое агентом сверху
tim check                   # обойти все сайты одной таблицей
```

## Зачем он нужен

**VPN перестаёт мешать.** `tim ssh` сначала смотрит, куда сейчас ведёт маршрут до сервера.
Если в туннель VPN или на шлюз прошлой сети - предложит пустить этот адрес напрямую
и только потом подключится. `tim direct git.example.com` оставляет адрес снаружи навсегда,
`tim direct Firefox` - целое приложение.

**Туннели без настроек прокси.** `tim tunnel all prod` заворачивает весь трафик через ssh
(сам сервер и приватные сети остаются снаружи). `tim tunnel port 15432:5432 prod` - база сервера
на локальном порту для GUI-клиента. `tim tunnel expose 8000` показывает локальный порт наружу.

**Видно, что поднял агент.** `tim ports` показывает, кто слушает порты, в какой папке
и кто запустил: ты в терминале или агент, и какая у него сессия. Сессия закрыта или агент
давно молчит, а сервер всё работает - строка уходит в забытые. На экране Машина › Запущенные
`x` закрывает её, `tim ports --json` отдаёт то же агенту, чтобы он гасил свои хвосты сам.

**Утро начинается с одной команды.** `tim check` проходит по сайтам из конфига: отвечает ли сайт,
когда истекает сертификат, в порядке ли почта, до каких пор оплачен домен. С `--servers` - ещё
и серверы. Строки с проблемами сверху, подробности под строкой.

**Понятно, куда ушло место.** `tim disk` доходит до конкретной игры, виртуалки или storage
проекта и подсказывает, как освободить. Свободное место считает так же, как `df`.
`tim disk --leftovers` находит хвосты удалённых программ: папки в `~/Library` по ID программы,
агенты автозапуска, чья программа пропала, процессы, чей файл уже удалён.

**Локальный https без возни.** `tim link` даёт папке имя `shop.test` и сертификат своим CA,
`tim cert ca install` - чтобы браузер ему доверял.

**Ничего личного в коде.** Адреса, серверы, пути - всё в твоём конфиге `~/.config/tim/config.toml`.
В репозитории нет ни одного IP.

## Установка

```sh
brew install --cask TimurTurdyev/tap/tim
# или
go install github.com/TimurTurdyev/tim@latest
```

```sh
tim init          # вписать tim в shell (zsh или bash, определит сам)
tim               # главный экран
```

Конфиг не обязателен. Серверы tim берёт из `~/.ssh/config`, сайты для обхода - списком
в `~/.config/tim/config.toml`:

```toml
sites = ["shop.example.com", "example.com"]
```

`tim init` дописывает одну строку в конфиг твоего shell. Процесс не может сменить папку
родительской оболочки, поэтому перейти в папку с экрана tim помогает маленькая функция.
Заодно она подключает дополнение по Tab, твои алиасы и, если захочешь, сводку в каждом
новом терминале:

```toml
motd = ["system", "net", "ports"]   # разделы сводки; службы - tim status --full

[shell]
motd = true          # сводка при открытии терминала, один раз на окно

[shell.aliases]
gs = "git status -sb"
```

Обновление: `brew upgrade --cask tim` или `tim self-update` для любого другого способа установки
(берёт последний релиз с GitHub, сверяет sha256 с `checksums.txt`, откатывается, если подмена не удалась).

## Главный экран

`tim` в терминале - главный экран, в трубе - короткая заставка. Буква открывает раздел сразу:
`s` - серверы, `w` - сайты, `n` - сеть, `m` - машина, `d` - диск, `u` - утилиты. `/` ищет команды,
разделы, серверы и сайты. `:` - команда tim с подсказкой аргументов: алиасы, домены. Пример
из справки встаёт в поле ввода для правки и сам не запускается. `h` и `l` листают вкладки,
`j` и `k` - строки.

Сверху беды: своп, диск, обход, почта сайтов, сервер. Enter ведёт разбираться. Ниже недавнее и память,
диск, сеть. Первый esc только подсказывает, второй выходит. Маскот слева показывает то же лицом: тревожится, когда диск или своп на пределе или страж маршрутов не работает, расстраивается, если
обход сломан, радуется удачной команде, ночью спит.

## Справка

`tim --help` - все команды по разделам,
`tim <команда> --help` - подробности с примерами. То же есть в `man tim` и `man tim-<команда>`.
Справка и ошибки по-русски, цвет только в терминале, `NO_COLOR` его выключает.
Под светлый терминал tim подстраивается сам; если терминал не говорит, какой у него фон, -
`TIM_THEME=light` или `dark`.

`--dry-run` или `TIM_DRY_RUN=1` печатает каждую команду, которая меняет систему, вместо её запуска.
Это работает везде, где tim трогает маршруты, туннели, системные файлы или ходит на сервер.

`--no-input` или `TIM_NO_INPUT=1` - для скриптов и cron: tim ни о чём не спрашивает, на подтверждения
отвечает "нет", вместо выбора печатает список. Без терминала на stdin так и происходит само.
`-y` отвечает "да" на все вопросы.

Глаголы: up/down - туннели и маршруты, on/off - переключатели, kill - процессы.
Сроки: `30m`, `24h`, `3d`, `1w`; `--since` берёт и дату `2025-10-01`. У отчётов есть `--json`.

## Команды

### Сеть и VPN

- `tim ssh [алиас|user@host] [команда]` - без цели открывает выбор алиасов. Проверяет маршрут
  до адреса и, если он уходит в VPN или на шлюз прошлой сети, предлагает добавить прямой маршрут.
  Приватные адреса оставляет VPN.
- `tim direct <сайт|приложение|сеть...>` - пустить мимо VPN:
  - `tim direct example.org` - сайт и всё, что он грузит: tim смотрит в браузере, какие сети сайт тянет
    по туннелю, и добавляет их;
  - `tim direct Firefox` - весь трафик программы, она запускается под группой `novpn`;
  - адрес, подсеть, `as:N` или домен с `--label` - в конфиг и маршрут;
  - `tim direct` - что идёт напрямую; правила ядра для приложений - `--rules`, спросит пароль;
  - `direct rm <цель|пометка>` - вернуть под VPN, `direct off` - выключить правила приложений;
    ещё `list`, `watch`, `check`. Только IPv4.
- `tim route` - куда идёт трафик в интернет и сколько адресов в обходе, отклонения - строками, весь
  список - `--all`; `route up|down|clean|fix|check|table`,
  `tim route fix` - после смены сети.
- `tim vpn` - какие туннели подняты, полный или раздельный, DNS, сколько целей идёт мимо и работает ли страж.
- `tim direct yandex.ru --owner` - не адреса домена, а все сети его владельца. У крупных сервисов
  поддомены и CDN живут на других адресах, поэтому исключение одного домена их не покрывает.
  tim находит автономные системы, из которых виден домен (у Яндекса их две), и пишет в конфиг `as:13238`.
  Сети берутся из анонсов RIPEstat, соседние склеиваются, список обновляется раз в сутки. Если владелец -
  CDN, tim откажется: в обход ушла бы чужая половина интернета.
- `tim route install` - страж маршрутов службой системы (LaunchDaemon на macOS, systemd на Linux).
  Раз в 10 секунд перечитывает цели и чинит маршрут, если его нет, если он ушёл в туннель или смотрит
  на шлюз прошлой сети. Нужен root; если запустить без sudo, tim спросит и повторит команду сам.
  `tim route status` - когда была проверка, сколько маршрутов в порядке, сколько починок за сутки
  и неделю и по каким причинам. `tim route uninstall` убирает стража, цели и маршруты остаются.
  При первой цели `tim direct` сам предлагает поставить стража; после обновления tim страж
  переходит на новую версию сам.
- `tim tunnel all [сервер] [-x подсеть]` - весь трафик через ssh с помощью sshuttle, без настроек прокси.
- `tim tunnel up [сервер]` - SOCKS5 на 127.0.0.1, снаружи это обычный ssh; `tunnel system on|off`
  направляет туда системный прокси macOS, `tunnel check` сравнивает внешний IP с ним и без.
- `tim tunnel port <L:host:R>`, `tim tunnel expose <порт>`, `tim tunnel down`.
- `tim net check` - интерфейс и шлюз, интернет, DNS, внешний адрес, VPN; шаг за шагом, с первым сбоем.

### Локальная разработка

- `tim link [имя] [--name shop.test]` - локальный домен папке одной командой: имя `<папка>.test`
  в `/etc/hosts` и сертификат своим CA. tim говорит, где лежат сертификат и ключ, их подключают
  к dev-серверу: `vite --https`, прокси перед `artisan serve`. `tim unlink` убирает оба.
- `tim cert new <домен|адрес...>` - сертификат для локальной разработки, подписанный своим CA
  в `~/.local/share/tim/ca`. К каждому домену добавляется и `*.домен`, потому что wildcard
  не покрывает сам домен. `tim cert ca install` кладёт CA в системное хранилище и в профили Firefox.
- `tim host add <имя...> [--profile]`, `tim host on|off <профиль>`, `tim host rm`, `tim host check` -
  локальные имена. Свой блок в `/etc/hosts` между `# tim:begin` и `# tim:end`, остальное не трогается,
  прежний файл остаётся как `/etc/hosts.tim-backup`. Профиль выключается целиком, не удаляя имена.
- `tim host resolver [зона]` - зона `*.test` целиком на 127.0.0.1 через dnsmasq. Точными именами
  поддомены не покрыть, поэтому `a.shop.test` в `/etc/hosts` не записать, а резолвер решает это разом.

### Что происходит с машиной

- `tim status [раздел...]` (прежнее имя `tim motd` тоже работает) - машина (нагрузка в долях ядер, память, диск, батарея, адрес, Docker)
  и беды под ней: диск, память, обход VPN, страж;
  текущая папка, сеть и VPN, что запущено, службы brew; по запросу `procs` и `versions`. Разделы идут
  параллельно, набор по умолчанию укладывается примерно в 100 мс. Та же карточка - на главном экране `tim`.
- `tim ports [--all]` - кто слушает порты, что это за сервер (PostgreSQL, Vite, контейнер Docker),
  в какой папке и кто запустил: ты или агент с его сессией. Один процесс - одна строка.
  `tim port <n>` - подробно про порт: папка, кто запустил, память, полная команда и файл вывода;
  `tim port <n> kill` - остановить. `tim ports --old [--older 8h] [--kill]` - забытое: процессы
  закрытых или молчащих сессий агента и запущенное вручную дольше 8 часов.
- `tim disk [папка] [--min 50M]` - сколько занимают node_modules, vendor, venv, target, dist, build,
  .next и .nuxt по проектам: крупное сверху, с итогами по видам.
  `tim disk --clean [--days 60]` предлагает убрать такие папки у проектов, которых не касались
  дольше N дней (ни коммитов, ни изменений в папке). Спрашивает про каждую и кладёт в Корзину,
  откуда можно вернуть. Папки вне git-репозиториев не трогает.
- `tim doctor` - что не так в окружении: конфиг (цели обхода, старые поля), шим в shell,
  `PATH` (дубли, несуществующие папки, перекрытые программы),
  менеджеры версий, которые спорят за один язык, несколько формул brew для одного клиента базы,
  упавшие службы. Только читает, ненулевой код только на ошибках.
- `tim top [--by app|project] [--cpu]` - кто занял память и CPU: все помощники браузера в одну строку,
  dev-серверы по проектам. Память - RSS, у многопроцессных приложений сумма выше, чем в Мониторе.
- `tim disk --system` - куда делось место кроме проектов: образы OrbStack и Docker, кеши npm, composer,
  brew, go, pip, bun, кеши IDE (старые версии JetBrains помечаются), Корзина, Загрузки. Для каждого -
  команда очистки, сам ничего не удаляет.
- tim узнаёт тяжёлые процессы, которые по имени файла не опознать: `qemu-system-aarch64-headless -avd Pixel`
  показывается как "Android-эмулятор Pixel, без окна", ещё демоны Gradle и Kotlin, Spotlight, серверы языков.
  Если что-то больше часа ест целое ядро, `tim status` и `tim check` скажут об этом и подскажут, как закрыть.
- `tim ps <имя>`, `tim kill <имя|pid> [--force] [-y]` - найти зависшее приложение по имени (опечатки
  прощаются: `goglehrome` найдёт Google Chrome) и закрыть все его процессы разом. Сначала бережно -
  как Cmd+Q, приложение успеет спросить про несохранённое; не закрылось - tim спросит, убить ли
  принудительно. Системные процессы (launchd, WindowServer) не трогаются.
- `tim hw [--watch]` - железо и его загрузка: модель процессора с производительными и эффективными ядрами,
  видеокарта (насколько занята, сколько видеопамяти в работе и какие твои процессы её держат), память
  и swap, диск со SMART, экраны, тепло. `--watch` обновляет раз в секунду.
- `tim hw battery` - циклы, ёмкость от заводской, состояние, зарядка.
- `tim net top` - кто сейчас качает и отдаёт: процессы по трафику за пару секунд.
- `tim stats [--month]` - графики места, памяти, нагрузки и батареи за неделю и прогноз
  "место кончится через N дней" по регрессии, а не по разнице первого и последнего замера.
  `tim stats install` ставит замер каждый час (launchd, на Linux - systemd), `tim stats uninstall` убирает.
- `tim ip`, `tim net wifi` - внешний адрес с геолокацией (и через туннель, если он поднят); сеть, канал,
  стандарт, сигнал с оценкой.

### Для веба

- `tim hook [порт] [--status 200] [--expose]` - приёмник вебхуков: каждый запрос печатается разобранным
  (заголовки, JSON с отступами, поля формы) и пишется в журнал на 200 последних. `tim hook replay <n>
  --to http://localhost:8000` повторяет запрос в свой dev-сервер, `--expose` даёт публичный адрес через
  cloudflared. Как webhook.site, только данные платёжки не уходят третьему сервису.
- `tim og <url>` - как ссылка будет выглядеть в Telegram и соцсетях: заголовок, описание, картинка
  с размером и весом, и чего не хватает для большого превью.
- `tim watch <url> [--every 10s]` - следит за сайтом и шлёт уведомление, когда он упал и когда поднялся.
  Падение - две неудачи подряд, чтобы одно моргание сети не будило зря. Удобно на время деплоя.
- `tim cors <url> --origin https://app.example.com [--method PUT] [--header Authorization] [--credentials]` -
  пустит ли браузер запрос, а если нет, то какой заголовок мешает. Ловит и неочевидное: звёздочка
  в `Allow-Headers` не покрывает `Authorization`, а с куками не работает вовсе.

### Серверы

- `tim server <алиас|user@host> [--json]` - состояние Linux-сервера одним заходом по ssh:
  место и inode, память и swap, нагрузка на ядро, упавшие юниты, нужна ли перезагрузка, ждущие
  обновления безопасности, какие порты слушают на всех адресах, настройки sshd, nginx -t, сроки
  сертификатов. Только чтение: скрипт уходит через stdin и ничего не ставит. То, что требует root,
  идёт через `sudo -n` - без пароля он не спрашивает, а отказывает, и проверка помечается
  "не проверено".
- `tim server <алиас> --attacks [--since 24h]` - кто ломится, по журналам сервера: удачные входы по ssh
  (вход с адреса, который перебирал пароли, - красный), перебор, пробы `.env` и `.git` на сайте и что
  получило 200, ufw, баны fail2ban и CrowdSec, владельцы сетей. На экране сервера - клавиша `a`.
- `tim server <алиас> --traffic [--since 1h]` - кто ходит на сайты, по журналам запросов nginx или
  apache: запросов всего и в минуту, график по минутам, доли ответов, адреса с владельцами сетей,
  пути, 5xx с путями, 404, время ответа, если журнал его пишет. Сверху находки: 5xx, адрес-обжора,
  медленные ответы.
- `tim server <алиас> --run disk` - заготовка на чтение; весь список - в `tim server --help`.
- `tim server <алиас> --deep`, `--accept`, `--ban <адрес>` - глубокая проверка, отметить новое своим, бан.
- `tim domain <домен> --twins` - двойники домена; `tim notify` - итог обхода в Telegram и ntfy.
- `tim check --machine` - FileVault, файрвол, ключи ssh без пароля, автозапуск.
- `tim servers [алиас...]` - таблица по всем серверам: состояние, uptime, нагрузка, память, диск.
  По умолчанию весь `~/.ssh/config`, кроме git-хостов. Хост с несколькими алиасами идёт одной
  строкой. На экране: enter - сервер, `a` - кто ломится, `s` - ssh.
- `tim servers record` пишет замер каждого сервера в журнал, `tim servers install` ставит его раз в 6 часов.
  Через сутки-двое `tim server` скажет, сколько места уходит в сутки и когда кончится. Меньше двух
  месяцев - находка.

### Домены и сайты

- `tim check [домен...] [--servers]` - обход сайтов одной таблицей: ответ, сертификат, почта, срок
  домена. Без аргументов - сайты из `sites` в конфиге; `--servers` добавляет серверы из `~/.ssh/config`.
  `tim check install [--at 09:30]` обходит каждый день через launchd (на Linux - таймер systemd)
  и присылает уведомление, только если что-то плохо; `tim check uninstall` убирает. Проблемные
  строки сверху. Код выхода ненулевой, если что-то плохо, - команду можно повесить на запуск терминала.
- `tim domain <домен> [--map] [--all]` - вся картина по домену за раз: регистрация и NS,
  записи почты, поддомены из трёх источников параллельно (CertSpotter, crt.sh, hostsearch) плюс перебор
  примерно 70 частых имён, каждый адрес со своей сетью, страной и PTR, что отвечает каждое имя по HTTP,
  имена из тех же сертификатов, счётчики аналитики и соседи по адресу. CNAME в никуда и имена, которые
  можно захватить у чужого сервиса, - красным. Ответы кешируются на сутки.
  `--map` рисует самодостаточную HTML-карту без внешних скриптов и открывает её.
  Домен уходит в crt.sh, whois.cymru.com и api.hackertarget.com.
- `tim mail [домен] [--all] [--selector s]` - MX, SPF, DKIM (частые селекторы и твои), DMARC,
  что в них не так, готовые DNS-записи для недостающего и одна строка вердикта.
- `tim site <домен|url>` - адреса со страной и провайдером, регистрация домена, сертификат,
  статус и редиректы, сервер и догадка о CMS.
- `tim audit <домен|url> [--json] [--md|--html]` - аудит снаружи: открытые `.env`, `.git`, дампы и
  журналы, отладка, заголовки безопасности, куки, переход на https, версии TLS и цепочка, версии без
  поддержки (по endoflife.date), порты баз наружу, robots и sitemap, мягкая 404, www и без www, разметка
  главной, битые ссылки, сжатие и HTTP/2, кэш статики, скорость первого байта, CAA, DNSSEC и NS,
  поддомены с CNAME на чужой сервис, где имя никто не занял (GitHub Pages, Heroku, S3, Azure и ещё
  два десятка). У каждой находки - почему и что сделать; `--md` и `--html` пишут это отчётом для клиента.
- `tim http <url> [-L]` - один запрос на свежем соединении по фазам: DNS, TCP, TLS, первый байт, загрузка.
- `tim cert <host[:port]>` - сертификат подробно; несколько доменов или без аргументов (по `sites`
  из конфига) - сроки списком. `tim dns <host>` (с CAA и DNSSEC), `tim port check <host:port...>`, `tim dns flush|servers`.

### Мелочи

Всё на стандартной библиотеке, без аргумента читают stdin.

- `tim hex 255`, `tim dec ff 0x1F 0b101` - системы счисления.
- `tim b64 [-d] [--url]`, `tim jwt <токен>` (подпись не проверяется), `tim hash [md5|sha1|sha256|sha512|crc32]`.
- `tim ts [epoch|дата] [--tz зона]`, `tim uuid [-7] [-n N]`, `tim json [-c]`.
- `tim url encode|decode|parse`, `tim pass [длина] [-n 1] [--no-symbols] [--no-ambiguous] [--copy]`.
- `tim qr <текст>` - QR прямо в терминале, чтобы перекинуть ссылку или пароль от wi-fi на телефон.
- `tim cron "<выражение>" [-n 5]` - что значит выражение cron и когда сработает ближайшие разы.

## Как это устроено

Тонкий слой команд на cobra поверх `internal/*`. Решения (пороги, разбор, классификация) живут
в `internal` и покрыты тестами, слой команд занят вводом, параллелью и выводом.

Всё, что меняет систему или ходит на сервер, проходит через `internal/runner` - единственное место,
которое запускает внешние команды, и единственное, которое знает про dry-run и подтверждения.

Интерактивные части (экраны, выбор сервера, подтверждения) собраны в `internal/tui` - только этот
пакет знает про charm. Рисуют они на `/dev/tty`, поэтому экран работает и когда вывод ушёл в трубу;
без терминала команды переходят на обычные списки и вопросы в строку.

Бюджет старта - меньше 10 мс, потому что шим выполняется в каждом новом терминале.

## Разработка

```sh
make build      # ./tim с версией из git describe
make install    # go install плюс man-страницы в $(go env GOPATH)/share/man/man1
make man        # man-страницы в ./man
make test vet lint
make bench      # время старта на пустом конфиге
make inittrace  # самые дорогие init пакетов
make snapshot   # локальная сборка релиза в dist/, ничего не публикуется
```

`tim version` печатает версию из `-ldflags -X github.com/TimurTurdyev/tim/cmd.version=...`,
иначе версию модуля из `go install`, иначе `dev`.

## Релиз

Тег `v*` запускает сборку: goreleaser собирает универсальный бинарник для macOS, публикует релиз
с `checksums.txt` и обновляет cask в `TimurTurdyev/homebrew-tap` (нужен секрет `HOMEBREW_TAP_TOKEN`
с правом записи в тот репозиторий). Бинарник не нотаризован, поэтому cask снимает карантин после установки.
